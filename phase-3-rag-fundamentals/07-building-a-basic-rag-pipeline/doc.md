# 07 — Building a Basic RAG Pipeline

## Problem

Topics 02–06 each covered one stage of RAG in isolation, with toy in-memory corpora.
Real usage needs every stage wired together end to end, over a real file, with answers
that **cite where they came from** — none of the previous minimal examples did that, and
without it there's no way for a user to verify an answer against the source.

## Concept

This is the phase project: **PDF Knowledge Assistant**.

```text
PDF -> Loader -> Splitter -> Embeddings -> Vector DB -> Retriever -> LLM -> Answer + Sources
       (T02)     (T03)       (T04)         (T04)         (T05)       (P1-T03)
```

Every arrow is a topic you already built:
1. **Loader** (Topic 02 / Phase 2 Topic 04) — `PyPDFLoader` turns the PDF into one
   `Document` per page, with `metadata["page"]` set automatically.
2. **Splitter** (Topic 03) — `RecursiveCharacterTextSplitter` chunks each page,
   *carrying that page's metadata onto every chunk it produces* — this is what makes
   page-level citation possible later.
3. **Embeddings + Vector DB** (Topic 04) — `OpenAIEmbeddings` + `Chroma.from_documents`.
4. **Retriever** (Topic 05) — `.as_retriever()`, top-k.
5. **Prompt + LLM** (Phase 1 Topic 03) — the same `prompt | model` LCEL chain, with
   retrieved chunks formatted into the context, each one tagged with its source page.
6. **Answer + Sources** — the LLM's answer, plus the *actual* page numbers the retrieved
   chunks came from (read straight from `metadata`, not asked of the LLM — the LLM never
   has to be trusted to remember page numbers correctly).

```text
"What's the warranty on the backpack?"
        │
        ▼ retriever.invoke(...)
[Document(page_content="...", metadata={"page": 2}), Document(..., metadata={"page": 0})]
        │
        ▼ format each as "[p.N] <text>" in the prompt context
        ▼ prompt | model
"The TrailBlazer 40L has a lifetime warranty... (Sources: page 1, page 3)"
        ▲
        └── page numbers taken from metadata, NOT generated by the LLM
```

## Minimal code

`code.py` generates a small multi-page PDF **with real extractable text** (using
`reportlab` — `pypdf` alone can only write blank pages, as seen in Topic 02), then runs
the full pipeline above and answers two questions, printing the answer followed by a
deduplicated, sorted list of the page numbers its retrieved chunks actually came from.

## Production notes

Always build the citation list from retrieved `Document.metadata`, never by asking the
LLM to report which pages it used — LLMs misremember exact page numbers even when they
answer the content correctly. Keep `metadata["source"]` (the filename) alongside `page`
once you're indexing more than one PDF, so citations disambiguate *which file* too
(this topic's mini challenge). Phase 4 improves this pipeline (re-ranking, hybrid
search, better chunking) — this is the baseline it improves on.

## Debugging

- Citations point at the wrong page → check the splitter ran on already-loaded
  per-page `Document`s (`splitter.split_documents(pages)`), not on one concatenated
  string — concatenating first loses the per-page metadata boundary.
- Answer isn't grounded in the PDF content → strengthen the prompt (Topic 01's pattern:
  "answer only using the provided context").
- Empty retrieval on a real PDF → check the PDF actually has an extractable text layer
  (Phase 2 Topic 04's debugging note — scanned/image PDFs need OCR, out of scope here).

## Mini challenge

Generate a second small PDF on the fly, load both into the same vector store with
`metadata["source"]` set per file, and confirm the printed citations correctly show
*both* the filename and page number for facts pulled from either document.
